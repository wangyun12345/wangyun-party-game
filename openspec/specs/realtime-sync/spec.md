## 新增需求

### 需求:Supabase Realtime 订阅房间状态
系统必须在客户端建立 Supabase Realtime 订阅，当 rooms 表中对应房间的 game_state 字段发生变化时，所有订阅该房间的客户端界面必须在 2 秒内自动更新。

#### 场景:房主更新游戏状态后其他玩家同步刷新
- **当** 房主的游戏状态机处理完玩家动作并写入 Supabase rooms 表
- **那么** 所有其他玩家的客户端收到 Realtime 推送，界面自动刷新显示最新状态

#### 场景:网络中断时提示用户
- **当** 客户端与 Supabase 的 Realtime 连接断开
- **那么** 界面顶部显示"连接已断开，正在重连..."提示，连接恢复后提示消失

### 需求:玩家动作通过 actions 表异步提交
系统必须允许玩家将游戏动作写入 Supabase actions 表，由房主客户端监听并处理。

#### 场景:玩家提交动作
- **当** 玩家在界面上执行操作（如投票、提名）
- **那么** 客户端向 actions 表写入一条包含 room_id、player_id 和 payload 的记录

#### 场景:房主处理动作
- **当** 房主客户端通过 Realtime 监听到 actions 表新增记录
- **那么** 房主的游戏状态机处理该动作，更新 rooms 表中的 game_state

### 需求:房主离线时通知其他玩家
系统必须检测房主客户端的在线状态，当房主断开连接时向其他玩家展示提示。

#### 场景:房主断线提示
- **当** 房主的 Supabase Presence 心跳超时（>10秒未收到）
- **那么** 所有其他玩家界面显示"房主已断线，游戏暂停，等待房主重新连接"
