## 新增需求

### 需求:玩家可以创建游戏房间
系统必须允许玩家输入临时昵称后创建一个新游戏房间，并获得唯一的6位数字房间码。

#### 场景:成功创建房间
- **当** 玩家输入昵称（2-12个字符）并点击"创建房间"
- **那么** 系统生成唯一6位房间码，创建者成为房主，跳转到房间等待界面

#### 场景:昵称不合规时拒绝创建
- **当** 玩家输入的昵称为空或超过12字符
- **那么** 系统显示错误提示，不创建房间

### 需求:玩家可以通过房间码加入房间
系统必须允许玩家输入6位房间码加入已存在的等待中的房间。

#### 场景:成功加入房间
- **当** 玩家输入有效昵称和有效房间码后点击"加入"
- **那么** 玩家被添加到房间玩家列表，所有在房间内的玩家界面实时刷新显示新玩家

#### 场景:房间不存在时提示错误
- **当** 玩家输入的房间码不存在或已结束
- **那么** 系统显示"房间不存在或已结束"提示，不进入房间

#### 场景:房间已满时拒绝加入
- **当** 玩家尝试加入的房间已达到当前所选游戏的最大人数
- **那么** 系统显示"房间已满"提示

### 需求:房主可以选择游戏并开始游戏
系统必须允许房主在等待阶段选择桌游类型，并在人数满足要求时开始游戏。

#### 场景:房主选择游戏
- **当** 房主从游戏列表中选择一款游戏
- **那么** 所有玩家界面显示当前选中的游戏名称及人数要求

#### 场景:人数满足时开始游戏
- **当** 房主点击"开始游戏"且当前玩家数满足所选游戏的最低人数要求
- **那么** 房间状态变为 playing，所有玩家跳转到游戏界面

#### 场景:人数不足时禁止开始
- **当** 房主点击"开始游戏"但玩家数少于游戏最低人数
- **那么** 系统显示"玩家人数不足"提示，不开始游戏

### 需求:玩家列表实时同步
系统必须在等待阶段实时向房间内所有玩家展示最新的玩家列表。

#### 场景:新玩家加入时所有人界面刷新
- **当** 有新玩家加入房间
- **那么** 所有已在房间内的玩家界面在 2 秒内自动显示新玩家的昵称
