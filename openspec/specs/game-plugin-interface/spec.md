## 新增需求

### 需求:所有桌游必须实现统一的 GamePlugin 接口
系统必须定义并强制要求每一款桌游以实现 GamePlugin TypeScript 接口的形式接入平台，大厅层禁止直接引用任何具体游戏的内部逻辑。

#### 场景:注册新桌游
- **当** 开发者创建新游戏模块并实现 GamePlugin 接口，然后将其注册至游戏注册表
- **那么** 该游戏自动出现在大厅的游戏选择列表中，房主可选择并开始该游戏

#### 场景:大厅通过接口调用游戏逻辑
- **当** 房主点击"开始游戏"
- **那么** 大厅层仅调用 `GamePlugin.initGame(players)` 获取初始状态，不感知游戏内部细节

### 需求:GamePlugin 接口必须包含完整生命周期方法
GamePlugin 接口必须包含以下方法：`initGame`（初始化）、`handleAction`（处理动作）、`getPhaseUI`（获取当前玩家视角界面描述）、`checkWinCondition`（检查胜负）。

#### 场景:处理玩家动作
- **当** 房主客户端收到玩家提交的动作
- **那么** 调用 `handleAction(currentState, action)` 返回新的游戏状态，不直接修改状态

#### 场景:获取玩家视角界面
- **当** 客户端需要渲染当前玩家的游戏界面
- **那么** 调用 `getPhaseUI(state, viewerPlayerId)` 获取该玩家视角的界面描述对象，不包含其他玩家的私有信息
